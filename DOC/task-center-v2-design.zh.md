# ZCode 工作台任务中心 V2 交互与实现设计

日期：2026-09-29
状态：两阶段已实现并完成本机主要验收；外部远控占用与真实手机软键盘场景待现场复核
实现仓库：本仓库的 `packages/experimental/zcode-workbench`、`integrations/zcode-desktop-adapter`；在完整 DSH 工作区构建和验收。

## 1. 目标与边界

任务中心从“派发与同步控制台”改为“工作区 → 任务 → 对话”的日常入口。手机默认逐级进入，桌面宽屏可同时显示工作区、任务列表和对话。用户应先看到任务内容与结果，执行路由、回执和技术 ID 仅在需要诊断时展开。

本设计参考 ZCode 远控页的交互层级，不复制其远控协议或承诺同等能力。保留当前 ACP 适配器、Codex ingress、任务状态机、路由锁、已完成任务原地续写、回执丢失锁与人工核销。当前适配器只支持文本任务；附件、模型切换、运行中插话、审批代办、置顶和归档管理均不在本次范围。现有能力与风险见 [插件说明](../packages/experimental/zcode-workbench/README.zh.md)、[适配器说明](../integrations/zcode-desktop-adapter/README.zh.md)和[连续任务交接](zcode-remote-continuity-handoff.md)。

交互稿有两种布局：A“工作区优先”是手机及普通桌面的主路径，B“三栏效率”是宽屏增强形态。两者使用同一任务数据与操作规则，不做两套产品逻辑。交互稿里的任务、数量和发送反馈都是模拟数据，不能作为接口或协议验收证据。

## 2. 信息架构

| 层级 | 主内容 | 主要动作 | 不放在主视图的内容 |
| --- | --- | --- | --- |
| 工作区首页 | 节点连接状态、工作区名称、可确认的任务数量与最近活动 | 打开工作区、在该工作区新建 | 配对链接、ACP session、完整路径与原始错误栈 |
| 工作区任务列表 | 统一任务行：标题、用户可理解的状态、来源、更新时间、最近内容 | 打开任务、状态筛选、刷新、新建 | 两份重复的“桌面任务／工作台任务”列表 |
| 任务对话 | 原问题、可获得的回复、后续轮次、当前状态 | 已完成时继续、查看运行详情、返回 | 默认展开的三端同步卡与 ID 清单 |
| 新建任务 | 已选定的执行位置、标题（可选）、任务描述 | 发送、返回 | 单节点场景下重复选择节点和工作区 |

首页先列节点再列其工作区；只有一个可用节点时不显示多余的节点选择器。工作区卡片的“新建任务”直接带入该节点和工作区，但发送前仍清楚显示目标；若同一路径存在于不同节点，必须按节点区分，绝不根据路径猜测目标。固定工作区节点显示适配器提供的固定位置标签，不把 `__fixed__` 暴露给用户。

首页另设轻量的“待选择位置”区域，承接 Codex ingress 创建但尚未路由的任务。此类任务不属于任何工作区，不能被分配到默认工作区或从统一视图中消失；点击后保留原任务与描述，显式选择节点和工作区，再走现有 `routeTask`。该区域不混入工作区任务数量。

工作区数量、任务数量和“已连接”只能来自已验证且有时间戳的数据；尚未读取或读取失败时显示“未获取／暂不可用”，不能使用工作台记录推断桌面任务总数。桌面任务索引仅覆盖已同步、未置顶、未归档的行，列表需要明示该范围；不承诺“这里是桌面全部任务”。

## 3. 关键交互

### 3.1 进入与切换工作区

打开任务中心后，先读取节点登记信息；仅对正在查看的节点发现工作区。点击工作区进入统一列表，保留该工作区选择；切换工作区时清空任务选择和续写草稿，停止旧工作区的主动刷新。宽屏采用工作区栏、列表、对话三栏；小屏采用工作区首页、列表、对话逐级导航，保留显式返回。断线时保留最后已知内容，显示数据时间和重连状态，不把缓存说成实时数据。

### 3.2 统一任务列表

一条桌面会话只出现一行，即使它由工作台新建并经历多轮续写。身份键为 `(nodeId, workspaceIdentity-or-normalizedPath, desktopTaskId)`；不能只凭标题、短 ID 或路径合并。桌面索引与工作台记录能够通过已验证绑定匹配时，列表行聚合来源及轮次；没有匹配的工作台任务仍单独显示，特别是未路由、未送达、回执丢失或桌面索引中暂不可见的任务。桌面索引失败时，工作台任务保持可见，原生桌面任务区域显示“暂不可用”及刷新入口，不能伪造或静默删掉它们。

筛选至少有“全部、进行中、已完成、需处理”；排序先显示需要用户处理和在途任务，再按最近活动时间倒序，并保持同时间任务的稳定相对顺序。来源只用轻量标签“ZCode 原生／工作台／Codex”；主状态只用一枚状态标签，送达阶段放进运行详情。若列表总量超过适配器当前 200 行上限，必须明确显示“仅显示最近 200 条”或提供有证据支持的分页，不能暗示完整。

### 3.3 任务详情与连续对话

详情第一屏按“标题与主状态 → 对话内容 → 继续输入 → 折叠的运行详情”排列。工作台任务使用现有 transcript；助手文本按安全的 Markdown 子集渲染，禁止原始 HTML，链接遵循应用的安全打开规则，代码块可横向滚动。重复的状态事件归入运行详情，工具调用保留简洁卡片。移动端输入框位于对话尾部，在输入时不能遮挡发送按钮或最近回复。

原生桌面任务的任务索引只有标题、状态和时间，不等于对话历史。未提供只读快照接口前，详情明确显示“当前只能读取任务摘要”，可在验证完成状态后进入续写，但不得用工作台 transcript 假装是完整桌面历史。新增只读快照接口后，按桌面原序展示可读的最近对话窗口，并在源协议仅返回尾窗口时显示“仅显示最近内容”；打开详情不能自动 `session/adopt`、改变桌面任务或抢占执行中的控制权。

`workbenchTaskId` 是每轮工作台审计记录，不是用户所见对话的永久身份。多轮续写在同一个桌面任务详情里按时间串联，保留各轮记录及其错误，不合并或丢弃审计。尚未绑定桌面任务的工作台记录以自身 ID 独立展示；绑定关系不可证实时宁可分开显示并提示，也不按同名任务猜合并。

### 3.4 新建与续写

从工作区进入新建时预填节点和工作区。发送请求仍使用现有 `composeTask` 或未路由 Codex 任务的 `routeTask`，服务端重新验证位置且首轮派发后锁定。切换节点或工作区清空任何已选续写目标，不能把旧草稿投到新位置；发送中禁用重复提交，失败后保留用户输入。

“继续这个任务”仅在桌面索引和实时任务检查均证明已完成、无待处理交互且无在途／结果未知续写时启用。点击发送使用现有 `continueDesktopTask`，其 `session/adopt` 在提交路径再次验证，绝不退化为新建替代任务。运行中、错误、未知、已置顶／归档不可验证的任务显示禁用原因；不提供“排队发送”或“立即纠偏”。提交成功后仍在同一桌面任务详情展示新的一轮，并标注“确认中／运行中”；回执丢失时禁用续写，提示先到桌面核实，不自动重试。

### 3.5 状态和异常

| 底层事实 | 用户主状态 | 次级说明或动作 |
| --- | --- | --- |
| 未路由 | 待选择位置 | 选择节点与工作区 |
| 派发中或仅收到提示信封回执 | 提交中／确认中 | 不写“已送达”或“已完成” |
| 桌面确认运行 | 进行中 | 可查看最新已知内容 |
| 桌面需要现场交互 | 待现场处理 | 不伪造工作台审批按钮 |
| 已完成 | 已完成 | 可按规则继续 |
| 执行失败／取消 | 失败／已取消 | 显示可行动的说明；仅在现有规则允许时重试 |
| 链路断开且结果未知 | 结果未知 | 锁住续写与重发，指向桌面核实 |
| 终态被工作台标记 `reported` | 保留原执行结果 | “已回报”只在运行详情展示 |

现有 `reported` 状态会覆盖 `completed/failed/cancelled` 的原状态。实现时应在记录和 wire view 中保留不可被回报覆盖的终态结果，或提供等价的可审计结果字段；旧存量记录无法可靠恢复时显示“结果待核实”，不能把所有 `reported` 一律映射为“已完成”。

## 4. 数据与接口方案

优先复用现有 `nodes`、`listWorkspaces`、`workspaceTasks`、`tasks`、`task`、`composeTask`、`continueDesktopTask`、`routeTask`。在 Client/Host 之间增加一个纯投影层，把桌面任务索引和工作台轮次合成 `TaskCenterItem`，字段至少含稳定身份、节点、工作区、来源、主状态、更新时间、可操作性及证据来源。合并算法做成可单测的纯函数，不修改持久任务或适配器绑定。不能从客户端自行拼接私有配置或配对 URL。

建议分两段交付接口改动：

1. **列表与工作台详情。** 复用 `workspaceTasks` 和 `task`，实现统一列表、工作台对话、明确的原生任务摘要占位、预选工作区的新建与现有安全续写。把 `reported` 的终态结果保存清楚。此阶段不声称原生任务有完整历史。
2. **原生任务只读详情。** 为适配器增加独立的只读任务快照入口，为 Host 增加对应 Remote；按指定节点、工作区和完整 `desktopTaskId` 验证身份后读取 V4 conversation snapshot，并返回有界、脱敏、按序的用户／助手／工具摘要及 `partial` 标志。快照尾窗口不能冒充完整历史；读取失败返回明确的 `unavailable`。打开详情只读，不通过 `session/adopt` 获得写入绑定。执行中的单控制通道被占用时延后读取或明确拒绝，不并发配对。

`--list-tasks` 虽然只读，仍会占用该设备唯一的远控 controller slot。首页不得对所有工作区按 2–3 秒间隔轮流探测；桌面列表只在进入工作区、用户主动刷新或已知派发完成后读取，并按节点串行。工作台本地记录可继续用轻量轮询；桌面索引缓存须带采样时间，活动派发期间暂停会争用 controller 的只读探测。外部 ZCode 网页远控占用同一控制权时，界面给出可理解的冲突提示，不能通过重连风暴“抢回来”。事件推送可以后续增加，但不得作为首版完成条件。

## 5. 页面与文案规范

- 任务列表行的点击区域覆盖整行；状态、来源和时间可被屏幕阅读器读出。筛选有明确选中态，键盘可操作。
- 任务详情默认不展示完整路径、ACP session、`workbenchTaskId`、`desktopTaskId` 和三端回执卡；这些放入可展开的“运行详情”，诊断时可复制完整 ID。
- 首页工作区卡片的任务数在未经读取时省略；无任务、无工作区、桌面索引不可用、Host 断线分别有不同文案。
- 320–390 px 宽度无横向页面溢出；任务标题可换行，主按钮触控面积不小于 44 px；窄屏按“工作区 → 列表 → 详情／新建”导航，宽屏显示三栏但沿用相同状态。
- 中英文 locale 必须成对补全；不要把后端错误原文、私有 URL、token、prompt 正文写进日志或技术详情。

## 6. 验收与实施顺序

第一阶段完成列表和工作台任务详情重构：统一任务投影不重复、不误合并；工作区新建预选正确；`reported` 不误报成功；Markdown 安全渲染；移动端首屏先见任务内容；原生任务历史缺口被如实标注。第二阶段完成原生任务只读快照与同一会话的多轮展示。每个阶段都要更新相关类型、locale、README 与测试，再同步到本机 DSH 插件副本验证。

必须覆盖的自动化测试：不同节点同路径的身份隔离；桌面索引与工作台轮次去重；索引失败和 200 行截断提示；`reported` 的成功／失败／取消结果保持；未完成、待输入和结果未知任务拒绝续写；切换工作区清除续写目标；重复点击只派发一次；只读详情不执行 `session/adopt`；运行任务与只读探测不并发占用 controller；断线恢复不重发。已有 [插件测试](../packages/experimental/zcode-workbench/tests/)和[适配器测试](../integrations/zcode-desktop-adapter/test/)不得回退。

本机实际验收在完整 DSH 工作区进行：先检查已有改动，不覆盖用户文件；运行类型检查、相关单测和构建；用真实 ZCode 3.14.3 验证一条新任务、完成后的同 ID 续写、原生任务只读查看、390 px 手机布局，以及远控占用时的安全失败。不能仅凭模拟交互稿或 fixture 测试宣布端到端完成。

## 7. 给 ZCode 的实施约束

先阅读本设计、插件和适配器 README、完整 DSH 工作区的 `AGENTS.md`，以及待改文件所在子树的规则。先实现第一阶段并报告改动、测试和剩余接口缺口；通过复核后再实现第二阶段。源码以本仓库为主，完整 DSH 工作区用于依赖、构建和运行验证。不要提交或输出配对链接、token、私有配置、状态目录或现场日志；不要在实现中绕开路由锁、单控制通道串行、`session/adopt` 的二次验证或回执丢失人工核销。未经复核不提交或推送 Git。
