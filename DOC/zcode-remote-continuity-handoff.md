# DSH × ZCode 连续任务交接

日期：2026-09-29
仓库：`deephik-progo`，`main`，基线提交 `d0abf64c0b40d6e58002401dfc9ba5ceb5cd4000`
交接范围：本机 Codex／DSH 工作台／本机及现场 ZCode 的任务查看、派发和原任务续写。

## 本包是什么

- `DOC/zcode-remote-continuity-prototype.html`：本轮制作的可点击交互稿。展示统一任务视图、工作台／手机／Codex 入口切换、模拟建任务、排队／立即纠偏、回显断开和恢复。**它只使用浏览器内模拟数据，不连接 ZCode，也不是已经上线的功能。**
- `DOC/zcode-workbench-interaction-prototype.html`：前一版节点、工作区、任务中心交互稿，同样是模拟页面。
- `packages/experimental/zcode-workbench/`：当前 DSH 工作台插件的源码、测试和包说明。压缩包只收录 Git 跟踪的源文件，未包含 `node_modules` 或 `lib` 构建产物。
- `integrations/zcode-desktop-adapter/`：桌面可见 ZCode 的 ACP 适配器、测试及说明。它需要额外的 `remote-client` 源码检出；该检出不属于本包。
- `DOC/integration/zcode-desktop-manifest.json`：此前的集成清单。其验证日期和版本是历史记录，现场复验时以当前设备为准。

本包是**对应上述 Git 提交的工作区功能切片**，不是能脱离 DSH 主仓库独立启动的发行版。完整 DSH 运行环境和依赖应从原仓库该提交恢复；将本包中的新增交互稿、交接文档及相关源码对照合入后再开发。

## 目前实际具备的能力

工作台插件已有节点注册、节点和工作区选择、任务列表与详情、工作台任务登记、Codex 本机 ingress、状态记录，以及读取 ZCode 桌面已同步任务索引。对可验证为“已完成”的已有桌面任务，可以走独立的续写入口：保留原 `desktopTaskId`，适配器通过 `session/adopt` 核对任务及工作区，然后用 `sendText`／`startNow` 续写，不创建替代桌面任务。任务送达确认与执行结果分别表述；回执丢失时保持结果未知并阻止重复派发。详情以插件 README 和测试为准。

现场节点可按会话发现多个工作区，但仍依赖配对链接和外部远程传输。桌面协议对“发出后回执丢失”的命令无法证明绝未执行；当前核销流程需要现场人工核验，不应自动释放锁或盲目重发。远程中继对同一设备只有一个控制通道，执行期间的并发探测必须串行或拒绝。

## 交互稿里尚未落地的能力

本轮交互稿是目标体验，不代表已有后端支持。特别是：

1. “手机远程”只是响应式视图示意；尚无面向手机的正式入口、设备授权和跨端实时同步服务。
2. “排队发送”和“立即纠偏”只是模拟交互；当前真实续写仅对已完成且可核实的桌面任务开放。运行中的队列或 steer 需先确认 ZCode 桌面协议是否支持、如何确认送达与取消，不能只放开按钮。
3. 一条统一事件时间线尚未成为任务唯一事实来源。当前 DSH 任务记录、ACP 会话和 ZCode 桌面任务仍有各自状态，界面按可见时约 2–3 秒轮询。
4. 模拟状态切换、模拟任务创建都不调用真实节点。现场 ZCode 3.14.3、断线重连和真实浏览器体验还需要再次验收。

## 建议的下一步顺序

1. **先做本机端到端基线。** 固定一个本机节点和工作区，从 Codex 发起一条只读任务，核对 DSH 记录、ZCode 桌面可见任务和原任务 ID。记录创建、进度、完成、续写的真实事件与时延；不要用 HTML 演示数据代替验收。
2. **定义统一任务视图。** 以稳定 `workbenchTaskId` 关联来源任务、节点、工作区、`desktopTaskId` 和每一轮命令 ID。区分“已登记、已提交、桌面确认、运行、完成、结果未知、待用户输入”；不要把送达与完成合并。
3. **做事件回传与恢复。** 在现有适配器事件和任务存储之上提供可恢复的增量订阅，页面先订阅、断线后按游标补齐；保留轮询兜底。刷新页面、Host 重启和短时断网后仍回到同一任务。
4. **再验证续写模式。** 先把“已完成任务原地续写”做成稳定主路径；排队和立即纠偏分别做协议可行性测试。没有桌面确认能力时明确禁用，不以同名新任务模拟续写。
5. **把结果未知处理做成可用流程。** 页面展示最后一次已确认事件、原任务入口和只读核对证据；人工核验后才调用现有核销能力。绝不自动重发可能已执行的命令。
6. **最后推广到现场与移动端。** 在本机闭环通过后验证单控制通道、现场工作区发现、连接身份变化、ZCode 3.14.3 兼容性，再设计正式手机入口和授权。

## 验收标准

- 同一条任务在 Codex、DSH、ZCode 三端能以稳定身份互相定位；续写后 `desktopTaskId` 不变，桌面不出现替代任务。
- 工作区与节点在首轮派发后固定；切换或陈旧工作区不能把命令发到别的现场。
- UI 分别展示提交、桌面确认、执行和结果；断线只显示“未知”，不显示虚假的“失败”或“完成”。
- 刷新页面、Host 重启、短时断网不丢任务时间线；恢复后不重复派发。
- 实际 ZCode 桌面可见、测试通过、真实浏览器交互通过，才算功能验收。测试重点覆盖回执丢失、并发探测、同一任务重复点击、现场版本变化。

## 恢复和验证

在完整 `deephik-progo` 仓库、上述提交及符合仓库要求的 Node/pnpm 环境中运行。先阅读仓库根目录 `AGENTS.md`、插件 `README.zh.md` 和适配器 `README.zh.md`。主要离线检查：

```powershell
node --test integrations/zcode-desktop-adapter/test/adapter.test.mjs
pnpm exec vitest run packages/experimental/zcode-workbench/tests
pnpm run build
```

HTML 稿可直接打开；如需本机 HTTP 预览，可在仓库 `DOC` 目录运行 `python -m http.server 4177 --bind 127.0.0.1`，再访问 `http://127.0.0.1:4177/zcode-remote-continuity-prototype.html`。

适配器需要**独立**的 `remote-client` 检出，来源和固定提交见 `integrations/zcode-desktop-adapter/README.zh.md`；当前说明要求 Node 24 与 `--experimental-transform-types`。配对链接、令牌、节点私有配置、绑定和现场日志均不在本包中，也不应进入 Git 或交接材料。接手者需在自己的受控环境中重新配置和健康检查。

本轮仅制作 HTML 交互稿与这份交接文档，没有实现上文新增后端功能，也没有提交或推送这些新增文件。
